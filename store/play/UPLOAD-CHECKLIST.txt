Ridely — Play Store upload checklist
Work top to bottom. Graphics and listing copy in this folder are ready to paste.

BEFORE YOU OPEN PLAY CONSOLE
[ ] Create a Google Play Developer account ($25 one-time, identity verification required)
[ ] Decide the legal entity name and a physical address (needed for the store and the privacy policy)
[ ] Host privacy-policy.html and terms-of-service.html on a public https URL
    (GitHub Pages, your domain, or any static host). Play rejects a file:// or app-only policy.
[ ] Fill in the legal-entity / address placeholders in those HTML files before hosting
[ ] Confirm package name stays com.deliveryapp.ridely — you cannot change it after the first upload

STORE LISTING  (Play Console → Store presence → Main store listing)
[ ] App name: Ridely
[ ] Paste short + full description from listing.txt
[ ] Upload graphics/icon-512.png
[ ] Upload graphics/feature-graphic-1024x500.png
[ ] Upload all 6 phone screenshots in graphics/screenshots/phone/
[ ] Optional: 7-inch and 10-inch screenshots in the tablet folders
[ ] Category: Maps & Navigation
[ ] Contact email: support@ridely.com
[ ] Privacy policy URL: your hosted https link

APP CONTENT DECLARATIONS
[ ] Data safety — follow data-safety.txt
[ ] Content rating — follow content-rating.txt
[ ] Target audience: 18+
[ ] Ads: No
[ ] News / COVID / government / health: No
[ ] Financial features: Yes (Paystack payments + rider payouts)
[ ] Data deletion: working in-app path or URL
[ ] Location permission: foreground only ("while using the app"). Ridely does NOT request
    ACCESS_BACKGROUND_LOCATION, so no background-location declaration or video is needed.
[ ] Foreground service declaration: FOREGROUND_SERVICE_MICROPHONE — "In-app voice calls between
    customer and rider (LiveKit). The service runs only during an active call."
    (The unused WebRTC screen-share / mediaProjection service is stripped from the build.)
[ ] Photo/video permissions policy

RELEASE  (Play Console → Production, or start with Internal testing / Closed testing)
[ ] Push the EAS environment variables once (maps key, Supabase, LiveKit, Sentry, web URL):
      node scripts/sync-eas-env.mjs
    Check: eas env:list --environment production   (EXPO_PUBLIC_GOOGLE_MAPS_ANDROID_API_KEY must be set;
    the production build now fails on purpose if it is missing, instead of shipping a grey map)
[ ] Optional, for push notifications: create the Android app in Firebase, download google-services.json,
    and upload it as an EAS file variable named GOOGLE_SERVICES_JSON (or put it in the project root)
[ ] Build a production Android App Bundle (.aab), not an APK
      eas build --platform android --profile production
[ ] First upload goes to Internal testing so you can install from Play and sanity-check
[ ] Play App Signing: accept Google's signing key (EAS handles the upload key)
[ ] AFTER THE FIRST UPLOAD: Play Console → Test and release → App integrity → copy the
    "App signing key certificate" SHA-1, and add it (with package com.deliveryapp.ridely) to the
    Android restriction of the Google Maps API key in Google Cloud Console. Without this, maps are
    blank in the Play-installed app even though they work in EAS/internal APKs.
[ ] Optional: submit from the terminal instead of uploading by hand — save a Play service-account key
    as secrets/play-service-account.json, then: eas submit --platform android --profile production
    (goes to the Internal testing track as a draft)
[ ] Countries: start with Nigeria if that is the launch market
[ ] Production release notes (example):
      "Ridely 1.0 — book local deliveries, track your rider live, pay with card or cash, or earn as a rider."

TECH CHECKS THAT BLOCK REVIEW
[ ] Target API level meets the current Play requirement (Android 15 / API 35 as of 2025–26)
[ ] 16 KB page-size compatibility (Android 15 devices)
[ ] Remove unused broad storage permissions if Play flags READ/WRITE_EXTERNAL_STORAGE
[ ] Foreground service type declared for microphone (see App content above)
[ ] Privacy policy URL loads without a login
[ ] App does not crash on first launch on a clean device
[ ] Location, camera, mic, and notifications each have a clear in-app reason

EXPO / APP ICONS (already wired in app.config.js)
    assets/images/icon.png                 1024 app icon
    assets/images/adaptive-icon.png        adaptive foreground
    assets/images/splash-icon.png          splash
    assets/images/favicon.png              web
    assets/images/notification-icon.png    status-bar silhouette
Rebuild the native Android project after these icons (npx expo prebuild --platform android, or the next EAS build) so mipmap/ic_launcher updates.
